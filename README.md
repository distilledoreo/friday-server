# FRIDAY server

The PC side of FRIDAY, the local Android assistant ([local-android-assistant](https://github.com/distilledoreo/local-android-assistant)).
It runs the model, search, voice and the authenticated API the phone talks to. Everything listens on
`127.0.0.1` only; the phone reaches the API through Tailscale Serve (tailnet-only HTTPS → `127.0.0.1:8700`).

| Piece | Port | Runs as |
|---|---|---|
| Assistant API (`api/app.py`) | 8700 | `systemctl --user … assistant-api.service` |
| Qwen3.8 27B, MTP drafting, reasoning off (`llama/start-server.sh`) | 8080 | `systemctl --user … llama-qwen38-mtp.service` |
| SearXNG | 8888 | `docker compose` |
| Crawl4AI (optional) | 11235 | `docker compose --profile crawl` |
| Speech: Parakeet TDT 0.6B v3 (ASR), Kokoro v1.0 (TTS) | in the API | CPU, loaded at API start |

## What lives where

- **This repo:** the gateway core (`api/app.py`, `api/prompt_cache.py`), Docker compose, SearXNG config,
  the llama launcher, systemd units, backup script and setup.
- **The app repo's `desktop/` folder:** the gateway's feature modules — `agent` (FRIDAY tasks, PC access,
  accounts, daily brief), `memory`, `workspace` (files, Python analysis, scheduled jobs) and `imagegen`.
  `scripts/setup.sh` copies them into `api/` from an app checkout, so each piece of code has one home.

`api/prompt_cache.py` is what keeps replies fast on a hybrid recurrent model that only reuses an exact
prompt prefix: it keeps the chat prompt byte-stable, pins phone chat to slot 0 and background work to
slot 1, and restores a saved snapshot of the system prompt and tools for each new chat (primed by the app).

## Setup

```bash
git clone <this repo> friday-server
git clone https://github.com/distilledoreo/local-android-assistant
friday-server/scripts/setup.sh local-android-assistant
```

Then fill in, on the PC only (never committed):

- `~/assistant-server/llama/llama.env` — llama-server build folder, model, vision projector, MTP draft model, slot folder.
- `~/assistant-server/api/imagegen/config.json` — replace `$QWEN_IMAGE_DIR` with your Qwen Image 2.1 folder.
- `~/assistant-server/.env` — `VOICE_MODELS` (tokens are generated by setup).

Optional: `scripts/setup-storage.sh` puts Docker's data on a separate drive (`STORAGE=/path/to/drive`).

## API

Send `Authorization: Bearer <ASSISTANT_API_TOKEN>` (from `.env`) on every call except `/health`.

```bash
set -a; . ~/assistant-server/.env; set +a
A="Authorization: Bearer $ASSISTANT_API_TOKEN"

curl http://127.0.0.1:8700/health
curl -H "$A" 'http://127.0.0.1:8700/search?q=nvidia+news&n=5'
curl -H "$A" -H 'Content-Type: application/json' http://127.0.0.1:8700/fetch \
     -d '{"url":"https://example.com","max_chars":20000}'
curl -H "$A" -H 'Content-Type: application/json' http://127.0.0.1:8700/chat \
     -d '{"messages":[{"role":"user","content":"Hi"}],"stream":true}'
```

- `POST /chat` — OpenAI chat-completions body, passed to llama.cpp (tools and `stream` work).
  Also served at `/v1/chat/completions` and `/v1/models`, so any OpenAI client can use
  base URL `http://<host>:8700/v1` with the token as its API key.
- `GET /search?q=…&n=8&categories=…&time_range=day|week|month|year` — `{query, results:[{title,url,snippet,engine}], answers}`.
- `POST /fetch {url, max_chars}` — `{url, success, status_code, title, markdown, truncated, error}`. Refuses private/local addresses.
- `POST /transcribe`, `POST /speak`, `/voice` — on-PC speech for the app's voice mode.
- `/workspace/...` — the feature modules above.

## Operations

```bash
./test.sh                                          # backends directly
journalctl --user -u assistant-api.service -f      # API log
docker compose --profile crawl ps                  # containers
```

If a separate storage drive was not shut down cleanly it may not mount, and the model and Docker won't
start until it is repaired (for NTFS: `sudo ntfsfix -d <device>`, then `sudo mount -a`).
